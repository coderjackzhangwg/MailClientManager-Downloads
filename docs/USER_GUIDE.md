# 邮件客户端管理工具：Windows 使用说明

本指南适用于从 [GitHub Releases](https://github.com/coderjackzhangwg/MailClientManager-Downloads/releases) 下载的 Windows 版本。不同版本功能和菜单可能略有差异；使用前请查看相应版本的 Release 更新说明。

## 1. 安装与首次启动

**准备**：Windows 10/11 64 位、可以访问自己的邮件服务器、拥有必要邮箱访问权限。具体 EWS/IMAP/SMTP 服务端认证方法受邮箱服务商及组织管理员限制。普通用户无需额外安装 Python。

1. 进入 [Releases](https://github.com/coderjackzhangwg/MailClientManager-Downloads/releases)，在已选版本的 **Assets** 下载 `MailClientManager-Setup-版本.exe`。
2. 若有 `SHA256SUMS.txt`，下载它，在 Windows 文件资源管理器找到安装包，打开 PowerShell：

   ```powershell
   Get-FileHash -Algorithm SHA256 -LiteralPath "C:\你的下载目录\MailClientManager-Setup-版本.exe"
   ```

   核对输出与该版本的哈希文件一致。不要直接运行来自陌生网站或聊天群的未知安装包。
3. 双击安装程序，阅读用户许可及隐私说明。按向导完成安装，开机后台运行功能可按需选择。
4. 打开“邮件客户端管理工具”，它会在本机启动管理页面（通常为 `http://127.0.0.1:1239`；若端口被占用可能切换）。**127.0.0.1 是自己的电脑，不是开发者远程邮件服务器。**
5. 若要求再次确认协议，请先认真阅读后操作。

## 2. 添加邮箱账号

1. 在顶部选择**设置**，或从右上角账户切换菜单进入**管理邮箱账户**。
2. 选择账户类型：Exchange EWS，或标准 IMAP/SMTP。根据你邮箱提供商/管理员给出的资料填写账号、服务器和端口；不要直接复制其他单位的配置。
3. 密码请在程序本机配置界面填写，切勿通过 Issues、截图或邮件发送给开发者。
4. 点击**测试连接**。连接成功后保存。若失败，请核对服务器地址、VPN/网络、服务端是否允许相应协议，以及组织是否启用多因素认证或限制旧式密码认证。
5. 添加多个邮箱时，请分别检查每个账户的后台同步、离线缓存与服务器修改权限。

## 3. 阅读、搜索及回复邮件

1. 点击顶部**邮件**，左侧选择文件夹，中间是邮件列表，右侧是正文阅读窗格。
2. 点击邮件列表中的任意邮件，中间当前行将出现“正在阅读”标记。方框勾选是多选批量操作，和正在阅读不是一回事。
3. 邮件列表显示实际收发时间：当天为“今天 14:30”，昨天为“昨天 09:20”，较早显示日期和时分；鼠标悬停可查看完整日期（含秒），按你的**电脑本地时区**显示。
4. 邮件中的远程图片默认被拦截以保护隐私。如果确认可信，可以点击“显示本封邮件的图片”，仅放行当前预览；加载图片可能向第三方暴露 IP 和打开时间。
5. 使用**写邮件**发送或回复时，先核对收件人和发件邮箱。附件或大邮件可能受到邮箱服务端及程序下载/发送大小限制。

## 4. 邮件缓存与离线阅读

进入 **设置 → 邮件下载/缓存**，每个邮箱可以独立选择：

- **仅在线阅读**：正文按需向服务器读取，不额外建立长期正文缓存，但邮件列表信息、日志和临时文件仍可能存在本地。
- **打开后保存**：第一次打开完整邮件后缓存到电脑，后续阅读优先读取本地副本。
- **后台保存**：按你指定的时间范围和邮件文件夹，在后台分批下载完整邮件与附件，完成后可离线阅读。

初次建议仅选择一个测试文件夹、最近 30 天、每轮 5 封。点击**保存设置**后再点击**立即下载**，到顶部**后台任务**查看状态。需要停止时使用**暂停下载**；不要强制关闭正在执行的邮件任务。

> 普通缓存是为了提高速度，可能有容量清理规则；**长期归档是独立保存，不应被普通缓存清理器删除**。离线阅读以邮件已完整下载且文件没有损坏为前提。

## 5. 本地归档与服务器清理

**这是最重要的安全区别：**

- **服务器邮件**：仍存放在你所连接邮箱服务器上的邮件。
- **已下载邮件**：本机有完整正文的邮件，可以离线打开。
- **本地归档**：用户主动保存的独立 EML，适合长期保留和备份。

如果需要释放服务器邮箱空间，正确步骤为：

1. 先选择少量无价值的**测试邮件**。
2. 将邮件**备份到电脑**，确认完整 EML、正文和附件可正常打开。
3. 核对邮件身份及存档校验结果，确认有独立、可靠的本地副本。
4. 在具有明确授权的情况下，选择“从服务器删除，保留本地”。注意“移入已删除邮件”与“永久删除”效果不同；部分邮件服务商仍会计入已删除项目容量。
5. 完成后退出并重新打开程序，甚至断网检查本地存档仍可阅读。

不要因为显示“已缓存”就贸然进行永久删除；也不要把该工具当成唯一备份。公司邮箱必须符合组织的保密和保留制度。**自动永久删除应继续保持关闭，除非已完成独立测试并确有授权。**

## 6. 本地客户端网关（高级）

顶部**本地客户端**页面提供实验性质的 IMAP/SMTP 本地网关供兼容第三方客户端。它仅绑定 `127.0.0.1`，示例端口为 IMAP `21143`、SMTP `21025`，请以程序实际显示为准。并非所有 Foxmail/Thunderbird 命令都实现，部分客户端认证前使用 `ID` 命令、修改已读状态等操作可能不兼容。网关预览功能有命令限制，不可把它误认为完整邮件服务器。

## 7. 检查和安装更新

1. 顶部打开**软件更新**。
2. 点击**检查更新**；也可以手动启用“每天自动检查一次”。未启用时程序不会每日主动向 GitHub 请求版本信息。
3. 若要接收 Beta，请勾选**接收测试版**并保存设置。未勾选时可能看不到公开 Beta。
4. “GitHub 更新说明与版本历史”会展示本次检查从 GitHub 取得的公开版本说明；点击某项可以展开。如果 GitHub 未提供描述，可能显示“该版本没有填写更新说明”。
5. 有更高版本时，阅读新版本说明，确认安装包来源。下载完成后，先检查本机配置及数据备份、等待邮件任务结束，从托盘**退出程序**。
6. 手动运行下载的安装包进行覆盖升级。当前版本**不会悄悄执行下载的 EXE**。升级一般无需先卸载旧版。
7. 更新后确认邮箱配置、缓存和本地归档仍然存在，并用测试邮件验证关键操作。

更新源固定为 [GitHub 版本页](https://github.com/coderjackzhangwg/MailClientManager-Downloads/releases)。检查更新向 GitHub 请求公开版本信息，不会把邮件正文、密码和附件发送到 GitHub；GitHub 可以看到基本网络访问数据。

## 8. 查看后台任务与导出排障报告

在**后台任务**查看当前同步、归档、下载等操作，允许取消的任务可通过界面取消。**日志**页面可以查看操作摘要并导出脱敏的诊断文件。

请注意，“脱敏报告”仍可能包含邮箱服务器地址、运行时间、部分元数据、设备信息或异常路径。提交到公开 Issues 以前，先用记事本检查，删除企业机密和其他敏感内容；**永远不要上传邮箱密码、令牌、原始 EML 或附件**。如涉及内部网络，应优先向组织 IT 管理员求助。

## 9. 常见问题与排障

**问：显示“连接正常”，后台下载还是失败？** 连接心跳和后台正文下载是不同任务。请在“后台任务”“日志”查看具体错误。如果出现 `['account'] are invalid kwargs for this class`，这是较早版本的自定义 EWS 文件夹兼容问题，请先暂停后台下载并检查是否已有新版修复。

**问：无法显示远程图片？** 先判断是否被隐私拦截，点击“显示本封邮件的图片”后再试。某些服务器要求登录或链接已失效，不保证所有图片均可显示。

**问：邮件列表只有邮件头，没有正文？** 正文可能未下载。检查该邮箱的缓存方式、离线下载范围和大小限制，并确认网络可用。

**问：从服务器删了邮件，本地还能打开吗？** 只有此前取得完整、未损坏的本地缓存或存档才可以。建议先制作长期归档并校验，不能仅凭列表中有邮件就认为已经备份。

**问：GitHub 有更新，软件却显示最新？** 检查当前版本号是否已经不低于 GitHub 的版本；Beta 版本需开启“接收测试版”；公开仓库中还必须存在完整的 Release，而不只是 Git 标签。新建版本时要上传 Setup 安装包和 SHA-256 校验文件。

**问：卸载或升级会清空邮件吗？** 正常设计不应清除用户长期归档；仍请在升级前独立备份应用数据目录与 EML。默认新用户目录通常为 `%LOCALAPPDATA%\MailClientManager`，老用户可能继续使用 `%LOCALAPPDATA%\EurosibMailManager`，归档路径则由你自行选择。

**问：系统提示 Windows 未知发布者？** 请核对安装包来自本仓库、SHA-256 正确和发行信息，不应关闭 Windows 的安全保护。不排除新版本尚未获得足够 SmartScreen 信誉。
