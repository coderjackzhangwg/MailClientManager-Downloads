## 1. 软件可以做什么

MailClientManager 是一款强调**本机运行、邮件数据保留和用户控制**的工具，主要支持：

| 功能 | 说明 |
|---|---|
| Exchange EWS | 支持使用完整 HTTPS EWS 地址连接获得授权的 Exchange 邮箱；具体认证方式和可访问性取决于服务端设置 |
| IMAP/SMTP | 支持标准 IMAP 邮件读取，以及独立 SMTP 发送；包含针对腾讯企业邮箱的预设类型 |
| 多邮箱 | 分别添加、编辑、切换邮箱，每个邮箱独立设置下载、归档路径和服务器修改权限 |
| 邮件阅读和搜索 | 浏览服务器邮件和已下载邮件，按文件夹、关键词、日期、未读、附件等筛选 |
| 邮件发送与草稿 | 在用户开启发信权限后编写和发送邮件；支持本地草稿 |
| 后台下载／离线阅读 | 按日期、文件夹和批次下载完整邮件（含原始邮件内容与附件）供离线阅读 |
| **永久本地邮件库（v0.9.10）** | 将完整下载的 EML 另外保存为长期本地副本；支持分类、纯文本预览和单封 EML 下载 |
| 可选新邮件加密 | 对今后写入永久库的文件使用 AES-256-GCM，加密口令由用户自己保管 |
| 邮件导入导出 | EML 文件／文件夹、带清单的 EML ZIP、MBOX 和 Maildir；导入默认只存电脑、不上传邮箱服务器 |
| 配置迁移 | 导出不含密码的账户设置 JSON，导入时创建默认停用的新账户 |
| 独立长期归档 | 完整 EML、元数据 JSON、SHA-256 校验及本地长期保存 |
| 邮箱容量清理 | 检查服务器邮件、筛选旧邮件、归档并验证后，按受支持的协议精确处理选定服务器邮件 |
| 归档路径迁移 | 把既有归档复制到新目录，逐文件校验，断点继续，通过后切换路径 |
| 旧归档善后 | 7 天／30 天提醒、停止提醒、复核后将当前邮箱旧子目录移入系统回收站 |
| 数据保护中心（v0.9.9 起） | 多邮箱配置＋SQLite 快照＋归档及永久库完整备份；验证、续传和新目录隔离恢复 |
| 本地客户端网关 | 向同一台电脑的 Foxmail、Thunderbird 提供**实验性**本地 IMAP/SMTP 接口 |
| 日志与排障 | 邮件活动、后台任务、连接错误、脱敏诊断 TXT 导出 |
| GitHub 更新 | 手动检查或可选 1／3／7 天检查，显示 Releases 更新说明，校验安装包，用户手动安装 |

### 本软件不是什么

- **不是**在开发者服务器上存邮件的云端邮箱服务，通常不要求用户在开发者网站注册账号。
- **不是** Exchange 邮箱容量扩容服务；它通过独立本地保存和有条件清理服务器副本来帮助管理容量。
- **不是**能够保证任何 IMAP 服务都可安全永久删除邮件的工具；服务端缺少必要协议能力时会拒绝危险操作。
- **不是**完整的 Outlook/MAPI/Exchange ActiveSync 客户端；不能承诺原生同步所有日历、联系人和任务。
- **不是**完整的 PST／OST 解析器，也不是运行中的 Outlook 数据文件共享引擎。

## 2. 邮件存储的四种状态：避免误以为已经备份

这是使用本软件时最重要的区别。

| 状态 | 文件通常在哪里 | 可以离线阅读吗 | 是否等同于长期归档 | 备份注意事项 |
|---|---|---|---|---|
| **服务器邮件** | Exchange/IMAP 服务器 | 未下载时不一定 | 否 | 服务器邮件可能被移动、清理或受到配额限制 |
| **已下载缓存** | Windows 应用数据中的 `mail_cache` | 正文完整且文件可用时可以 | **否** | 缓存和长期归档是独立机制；不能把“已下载”视为永久保存 |
| **永久本地邮件库** | 当前邮箱设置的归档磁盘下 `library` 子目录 | 是；加密邮件需先解锁 | 长期本地副本，但**不自动获得服务器清理授权** | v0.9.10 完整备份会纳入，需同时保存密钥恢复口令 |
| **正式 EML 归档** | 当前邮箱设置的归档根目录 | 是 | **是** | 记录文件和 SHA-256，参与服务器清理前的独立归档验证 |

**核心原则：** 本地有邮件列表信息 ≠ 已下载完整正文；下载缓存 ≠ 已形成长期独立归档；永久本地邮件库 ≠ 服务器删除操作已经获得许可。

当你想从公司服务器删除旧邮件时，必须按照第 17 节完成**正式归档核验和服务器端精确删除检查**。不要仅因为看见“仅本地”或“已下载”就跳过这些要求。

## 3. 安装要求与从 GitHub 下载

### 3.1 普通用户需要准备什么？

- Windows 10／11 的 64 位电脑，以及可用的本地磁盘空间。
- 对目标邮箱的合法访问权限及邮箱提供方允许的连接协议。
- 可靠网络（首次添加邮箱和读取未下载邮件时需要）。某些企业邮箱可能要求企业 VPN 或管理员开放 EWS/IMAP/SMTP。
- 如果准备长期保留大量邮件，建议使用非临时、非自动云同步的受控文件夹，并另做独立备份。

正常安装 **Setup.exe 不要求普通用户另外安装 Python、PyInstaller 或 Inno Setup**；这三个是开发者编译源码时使用的工具。

### 3.2 从官方 Releases 安装

1. 打开 <https://github.com/coderjackzhangwg/MailClientManager-Downloads/releases>。
2. 选择你需要的**明确版本**。测试版本一般标有 Pre-release/Beta；如不想测试新功能，优先选择已经完成你电脑验收的发行版。
3. 在版本的 **Assets** 下下载 `MailClientManager-Setup-<版本号>.exe`；不要把 GitHub 自动显示的 `Source code (zip)` 当作安装程序。
4. 同时下载该 Release 提供的 `SHA256SUMS.txt`（若提供）。
5. 在安装包所在文件夹打开 Windows PowerShell，执行：

   ```powershell
   Get-FileHash -Algorithm SHA256 -LiteralPath "D:\Downloads\MailClientManager-Setup-0.9.10.exe"
   ```

   把示例路径改成实际路径，将显示的哈希与 `SHA256SUMS.txt` 逐位核对。
6. 双击安装包，阅读安装向导中的用户协议和隐私说明，完成安装。
7. 若 Windows 提示未知发布者，先核对仓库、文件名、校验值和发行说明；**不要为了安装而关闭杀毒软件、防火墙或系统安全功能**。

SHA-256 用来检查文件有没有变化，**不能单独证明发行者身份**。若发布者提供了有效数字签名，也应另外检查签名。

## 4. 首次启动、协议和本地网页

1. 从开始菜单或桌面快捷方式启动“邮件客户端管理工具”。
2. 程序在本机启动网页服务并打开浏览器。常见地址为 `http://127.0.0.1:1239`；该端口被占用时程序可能自动选择其他本地端口，**以程序实际打开的地址为准**。
3. `127.0.0.1` 代表你当前这台电脑，并不是开发者的远程网站。
4. 首次使用如出现“用户许可协议”“隐私与本地数据处理说明”页面，请认真阅读并按界面提示确认。
5. 进入“设置”，添加第一个邮箱，然后进行连接测试。
6. 本地程序可能驻留在右下角系统托盘；**只关闭浏览器标签页不等于退出程序**。要结束所有后台操作，应从托盘菜单正式退出。

当前软件可在 Windows 控制中心和系统托盘中运行；可能有登录 Windows 后最小化启动的选项。是否自动运行以安装时和当前系统设置为准。

## 6. 添加、切换和管理多个邮箱

### 6.1 新增邮箱

1. 打开 **管理邮箱账户 → 添加邮箱**，或者进入 **设置 → 邮箱账号**。
2. 选择邮箱类型。现有类型为：Exchange EWS、标准 IMAP，以及腾讯企业邮箱预设类型。
3. 根据邮箱提供方的真实资料填写：

   | 设置项 | 说明 |
   |---|---|
   | 显示名称 | 仅用于在软件中区分账户，例如“工作邮箱” |
   | 邮箱地址 | 真实完整邮箱地址 |
   | 登录用户名 | 完整邮箱地址、公司允许的用户名，或 `DOMAIN\username`；以管理员提供的格式为准 |
   | Windows 域 | 主要针对 EWS 域用户名，可在已确认的情况下填写 |
   | EWS 地址 | Exchange 邮箱需要完整 HTTPS EWS 接口地址；**不是 OWA 网页邮件的 `#/mail/inbox` 链接** |
   | IMAP 主机、端口 | 由邮箱服务商提供，不能默认认定 OWA 主机也提供 IMAP |
   | SMTP 主机、端口、加密方式 | 使用邮箱服务商允许的 SSL/TLS 或 STARTTLS 配置 |
   | 密码／客户端专用密码 | 本地输入；组织开启多因素认证时，是否允许客户端密码由服务商决定 |
   | 已发送／已删除目录 | 针对 IMAP 账户，按实际服务器文件夹名称配置 |
   | 邮件备份保存位置 | 建议选择有足够空间并可独立备份的本地目录 |

4. 确认有权访问该邮箱，同意本地存储提示，点击 **保存设置**。
5. 返回 **总览 → 测试连接**，根据需要再执行“测试 SMTP”。
6. 如果只想读取邮件而不允许软件发信或修改服务器邮件，可以在“设置 → 邮件操作”中保持“允许发送邮件”“允许修改服务器上的邮件”关闭。

### 6.2 多邮箱切换和移除

在右上角账户切换菜单或“管理邮箱账户”中切换。每个邮箱的**下载方式、网关来源、归档位置和权限**都要分别检查。

“移除配置”意味着让软件不再管理该账户，**不应被理解为自动删除服务器邮箱或 EML 归档**。移除前仍建议做好完整备份，确认没有未处理的迁移任务或密码记录。

### 6.3 关于账号密码

软件使用本机系统的凭据存储机制保存密码。请勿把密码写进 GitHub Issue、截图或诊断报告。跨电脑恢复后通常需要重新输入邮箱密码。

## 7. 总览、连接状态与健康检查

进入顶部 **总览**，可以查看选中邮箱的连接状态、近期后台操作、网关是否运行等。

- **测试连接**：手动测试当前邮箱服务器能否访问并完成必要操作。
- **测试 SMTP**：独立检查发信相关设置；收信成功并不代表 SMTP 一定可用。
- **立即检查**：触发轻量健康检查，显示最近一次检查时间与状态。
- **自动检测**：在设置中可以启用或关闭；默认检查间隔约 **60 秒**，允许在 **30～600 秒**范围调整。

网页可以较频繁刷新状态，但**不应理解为每次页面刷新都重新向 Exchange 发出完整远程检测**。健康检查的成功，不保证某封超大邮件下载、某个权限受限文件夹读取一定成功。

若看到上游网络错误、TLS 握手超时等，请先确认公司服务器及网络恢复情况，再查看“后台任务”和“日志”，不要直接推断为密码错误。

## 8. 邮件列表、搜索、阅读和附件

### 8.1 浏览服务器和已下载邮件

进入顶部 **邮件**：

- 可选择“**服务器邮件**”查看当前邮箱服务端的邮件；“**已下载邮件**”查看已有本地正文缓存的邮件。
- 左侧选择邮箱文件夹；中间展示邮件列表，右侧阅读当前选中邮件。
- 邮件列表可筛选文件夹、关键词、日期范围、有附件、仅未读等。
- 搜索字段可选择“全部、主题、发件人、收件人、正文”。正文搜索依赖实际已同步／已索引内容，不能保证搜索到未下载邮件的完整正文。
- 点击“同步”或“刷新”更新列表；点击“更新邮件正文搜索数据”可重建相关本地搜索索引。

**邮件时间：** 当前或最近日期通常显示“今天 HH:mm”“昨天 HH:mm”等，较早邮件显示月日和时间；按浏览器所在电脑的本地时区显示，可通过悬停查看更完整时间。

### 8.2 阅读与附件

1. 点击邮件行，阅读正文、发件人、收件人等信息。
2. HTML 邮件中的图片可能默认被隐私策略阻止。确认可信时，可选择“显示本封邮件图片”。这可能让图片所在第三方服务器看到你的访问 IP 和打开时间。
3. CID 内嵌图片和远程图片使用不同处理路径；登录保护、失效或不安全来源的图片不一定能显示。
4. 下载附件时先确认来源可信；可执行文件或含宏文档不要随意打开。
5. 下载缓存如果缺失或损坏，软件可能需要再次联网获取正文；正式归档和永久邮件库拥有独立读取和校验逻辑。

### 8.3 批量操作

勾选多个邮件，选择所需操作后点击 **执行**。菜单可能包含“备份到电脑、已读／未读、加星标／取消、移动、服务器已删除邮件、导出 ZIP、设置永不删除、归为旧邮件”等。

**注意：** “点击阅读某封邮件”和“勾选它参与批量操作”是两种不同状态。批量操作对服务器写入需要独立权限；服务端不支持某个命令时，可能拒绝执行。

## 9. 写邮件、回复、转发和草稿

1. 点击顶部 **写邮件**，填写收件人、抄送、密送、主题、正文及附件。
2. 选择正确的发件邮箱，确认邮箱管理员允许使用该 SMTP/EWS 发信接口。
3. 未准备好发送时点击 **保存草稿**；顶部 **草稿** 可查看本地草稿。
4. 需要发信时点击 **发送**，查看页面结果和“日志 → 发送状态”。
5. 若发信失败，不要不加判断地多次点击发送，先确认上一次是否已实际到达服务器，避免重复邮件。

用户应区分**软件显示发信请求成功**与**对方最终收到邮件**；实际投递、退信和对方邮箱策略由上游邮件系统决定。

## 10. 后台下载、缓存与离线阅读

### 10.1 三种正文保存方式

进入 **设置 → 邮件下载 → 正文保存方式**：

| 方式 | 行为 | 适合谁 |
|---|---|---|
| 仅在线阅读 | 需要时从服务器读取，不主动给新邮件建立长期正文缓存 | 磁盘空间紧张、只临时查阅 |
| 打开后保存在电脑 | 第一次打开完整邮件后缓存，之后优先使用本地正文 | 常规邮件阅读 |
| 后台下载，支持离线阅读 | 按指定文件夹、日期和批次下载完整邮件，后台逐步完成 | 经常离线或希望预先保存邮件 |

### 10.2 建议的设置顺序

1. 选择“**后台下载，支持离线阅读**”。
2. 选择日期范围：最近 **30／90／365 天或全部日期**。
3. 设置每轮最多下载多少封：支持 **1～100 封**。新用户可以先试 5～20 封。
4. 设置两轮下载间隔、下载空间上限，以及需要下载的文件夹；不勾选时通常使用收件箱和已发送邮件。
5. 点击 **保存设置**，然后再点击 **立即后台下载**。
6. 前往 **后台任务**查看进度，必要时点击 **暂停后台下载**或“重新检查下载范围”。
7. 完成后点击“**查看已下载邮件**”，断网时试读其中已完整缓存的测试邮件。

### 10.3 缓存限制必须理解

- 下载空间配额是缓存控制，不是“保证永久保存”的承诺。达到容量或磁盘安全余量时，可能停止继续下载。
- 单封邮件大小受设置中的限制，默认约 **50 MB**，可配置范围最高 **100 MB**；过大的邮件可能跳过或报告失败。
- 日期和分页扫描不是邮件服务器级的零遗漏存档；邮件若同时被其他客户端移动或删除，应在下一轮重新检查。
- 软件会谨慎回收重复缓存：未确认存在独立、完整归档的唯一副本不能当成普通重复缓存删除。
- **即使启用后台下载，也要进入“本地邮件库”确认是否启用了“额外永久保存”。**

## 11. v0.9.10 本地永久邮件库

这是 v0.9.10 的重点新功能。进入顶部 **本地邮件库** 页面。

### 11.1 开启自动永久保存

1. 在“**保存规则与可选加密**”中勾选“**后台下载完整邮件后，额外保存为永久本地邮件**”。
2. 如果暂时不需要应用级加密，先不要勾选“加密今后新保存的永久邮件”。
3. 点击 **保存选项**。
4. 返回“设置 → 邮件下载”，将正文保存方式设为后台下载，并完成实际下载。
5. 再返回“本地邮件库”，查看正式保存数量、加密数量、邮件分类和保存根目录。

后台保存到永久库时，软件会尝试把完整 EML 另存到长期目录并做哈希校验；**永久保存失败会报错，不应该仍把该封标记为成功永久保存**。这种“永久库副本”与临时缓存通常会额外占用磁盘空间。若启用了永久库加密但尚未解锁，后台下载可能先留下缓存、随后因不能写入加密永久库而报告失败；请先解锁，再检查正式保存状态。

### 11.2 将以前下载的缓存转换为永久邮件

1. 进入 **本地邮件库**。
2. 点击 **转换已下载的完整邮件为永久邮件**。
3. 等待任务完成，检查“成功／跳过／失败”数量。
4. 失败的邮件仍可能只在原始缓存中，请查看原因后处理；不要强制清理缓存。
5. 到 **数据保护中心**创建备份前，先确认没有任何“只在缓存、尚无独立归档或永久库副本”的完整邮件。

### 11.3 分类、状态与浏览

本地邮件库可以按下列逻辑分类筛选：

| 分类 | 含义 |
|---|---|
| 收件箱 | 原始收件夹的邮件 |
| 已发送 | 服务器已发送文件夹中的邮件 |
| 草稿 | 标记为草稿来源的本地邮件 |
| 发件箱 | 待发或对应发件箱文件夹 |
| 已删除 | 原始已删除或垃圾桶目录 |
| 垃圾邮件 | 原始 Spam/Junk 分类 |
| 自定义文件夹 | 原邮箱的自建文件夹 |
| 外部导入 | 从 EML、MBOX、Maildir 等导入的文件，或无法确定分类的邮件 |

可输入**主题／发件人关键词**搜索，支持分页、“预览”和“下载 EML”。预览采用纯文本方式，避免直接执行不可信 HTML 邮件代码。

列表中的“**服务器仍有副本／仅本地**”代表本地索引记录的服务端状态，**不是每次打开都重新实时验证服务器**；如其他邮件客户端刚刚移动或删除邮件，状态可能稍有延迟。

### 11.4 “服务器删了，本地还在”是什么意思？

如果完整永久库文件已经保存并验证，即使服务器上的原邮件副本后来被删除，软件仍有机会在本地永久库中读取它。但是：

1. **永久库保存本身不会自动删除服务器邮件。**
2. 必须使用“容量”或相应受控的服务器清理功能，遵守正式归档、身份复核和精确删除条件。
3. “删除服务器副本”与“删除本地文件”是两类独立操作；千万不要在资源管理器中误删唯一的本地归档。
4. 企业邮箱的清理还应遵守组织的存档、审计、保留和授权规定。

## 12. 可选 AES-256-GCM 加密：如何正确使用

### 12.1 功能范围

在“**本地邮件库 → 保存规则与可选加密**”勾选“对今后新保存的永久邮件进行 AES-256-GCM 加密”，程序对**此后写入永久邮件库的新文件**进行应用级加密。

当前实现采用 AES-256-GCM，用户口令经 Scrypt 派生邮箱独立加密密钥；不把明文口令写进 SQLite 或设置 JSON。加密文件与普通 EML 是不同存储格式，需要软件解密后才可阅读或导出标准 EML。

### 12.2 第一次启用

1. 确保自己能够控制该电脑及未来的备份介质。
2. 勾选“**加密今后新保存的永久邮件**”。
3. 在“**加密口令／解锁口令**”中设置**至少 12 个字符**的口令。
4. 以安全方式离线保管口令，建议另外记录在受保护的密码管理器或离线恢复记录中。
5. 点击 **保存选项**；加密开启后的新邮件才会写入加密格式。
6. 退出并重新打开软件，使用 **解锁当前账户邮件**验证口令能够重新打开邮件，然后可点击 **锁定加密邮件**结束本次解锁。

### 12.3 重要限制：不是“全盘加密”

**勾选加密不会自动改变下列数据：**

- 以前已经保存的明文 `.eml` 正式归档和历史永久库文件；
- 临时下载缓存 `mail_cache`；
- SQLite 中的主题、发件人、搜索索引及其他元数据；
- 以前生成的备份和临时导出文件；
- 当前 Windows 系统中其他软件可能保存的相关副本。

**永久邮件库的完整备份可以复制加密文件及其加密参数，但不包含用户口令。** 换电脑、重装系统后仍需要原口令。遗失口令可能导致加密邮件无法恢复；应用不能承诺“忘记口令后自动找回”。

### 12.4 如需更广泛的磁盘保护

可以配合 Windows BitLocker／设备加密和本机账户访问控制使用。但应用级加密、磁盘加密及文件备份分别解决不同问题，不应把任何一种技术说成“绝对安全”。

## 13. 导入 EML、EML ZIP、MBOX、Maildir

进入 **本地邮件库 → 导入／导出邮件（仅本地）**。

### 13.1 导入步骤

1. 将待导入文件放在电脑上的受控目录，例如 `D:\MailImports\`。
2. 在“**需要导入的绝对路径**”输入实际路径，例如 `D:\MailImports\Inbox` 或 `D:\MailImports\old.mbox`。
3. 在“**来源格式**”选择 `EML 文件或文件夹`、`本软件导出的 EML ZIP`、`MBOX 文件` 或 `Maildir 目录`。
4. 在“**目标分类**”选择 `外部导入`（推荐默认）、`收件箱`、`已发送`、`草稿` 或 `自定义`。其中本软件 EML ZIP 的每封原始分类由包内清单决定。
5. 点击 **开始导入到本地**，等待任务完成后刷新本地邮件库列表。
6. 抽查中文标题、邮件时间、正文、附件和原始分类，再做一次完整备份。

### 13.2 支持的格式和边界

| 格式 | 导入路径示例 | 注意事项 |
|---|---|---|
| 单个 EML | `D:\MailImports\one.eml` | 须包含可识别的邮件头和正文 |
| EML 文件夹 | `D:\MailImports\Inbox` | 读取文件夹下 `.eml`；部分目录名称可用于推断分类 |
| **本软件 EML ZIP** | `D:\MailImports\mail-export.zip` | 必须有合规 `manifest.json`、文件 SHA-256 和安全路径检查；不是任意 ZIP |
| MBOX | `D:\MailImports\old.mbox` | 按 MBOX 文件中的邮件逐封导入；部分源端特有状态可能无法完整还原 |
| Maildir | `D:\MailImports\Maildir` | 需要相应 `cur`／`new`／`tmp` 结构；按内容导入，不承诺完整保留第三方专用标记 |
| PST／OST | — | **尚未原生直接支持**，请通过经典 Outlook 或受信任工具先导出受支持格式 |

**单次导入／导出上限：** 本地邮件库每次最多 **500 封**、总数据约 **512 MiB**；单封邮件内容有约 **150 MiB** 的程序内保护上限。超出时需要分批操作。不同格式导入时重新序列化邮件，某些字节可能与原始容器不完全一致；如果需要以后按 SHA-256 校验原始 EML，优先使用本软件带清单的 EML ZIP。

### 13.3 导入不会自动回写服务器

导入只是把文件保存到**当前所选邮箱的本地永久库**。它不会自动向企业 Exchange／IMAP 上传邮件，也不会发送邮件、更改原服务器文件夹或删除服务器上的任何邮件。

## 14. 导出邮件与保留原始分类

### 14.1 从本地永久邮件库导出

1. 在“本地邮件库”选择需要的**邮件分类**；若想导出所有分类，可保持“全部”。
2. 在“**导出文件或目录（必须尚不存在）**”输入绝对路径，例如：

   ```text
   D:\MailExports\MyMail-2026.zip
   ```

3. 在“**导出格式**”选择：`EML ZIP（含 manifest）`、`MBOX` 或 `Maildir`。
4. 点击 **导出当前分类最多 500 封**，等待任务结果。
5. 到资源管理器检查新生成的文件，并抽查邮件是否可以被其他客户端或本软件重新导入。

### 14.2 推荐 EML ZIP

本软件的 EML ZIP 含 `manifest.json`，记录每封邮件的分类、原始文件夹信息、SHA-256 等。适合将来导回本软件和核对内容。

MBOX／Maildir 对一些客户端更方便，但跨格式重新序列化可能改变原始 EML 的字节布局。若需要保留最完整的源邮件字节和分类清单，**优先 EML ZIP**。

### 14.3 “归档”页的旧版批量 ZIP 导出

在“归档”或邮件工作区批量选中并执行“**下载所选邮件（ZIP）**”也可以导出，但它与本地永久库导出**不是同一个任务接口**：旧归档批量导出通常每次最多 **100 封、250 MiB**，不要把两套限额混为一谈。

## 15. 导入、导出邮箱配置 JSON

进入 **本地邮件库 → 邮箱配置导入／导出（不含密码）**。

### 15.1 导出

点击 **下载不含密码的配置 JSON**，浏览器下载类似：

```text
MailClientManager-Settings-NoPasswords.json
```

包含邮箱类型、地址、服务器和端口、部分下载规则等非秘密设置；**不包含邮箱密码、设备专用密码、访问令牌或本地库解密口令**。

配置文件中可能仍包含公司邮箱地址、内网主机名等敏感业务信息，分享前也应检查。

### 15.2 导入到新电脑或新工程

1. 打开本地邮件库，选择导出的 JSON 文件。
2. 确认新电脑已有合适的归档目录，填写“**新账户归档位置**”。
3. 点击 **预览并导入为停用的新账户**，核对界面展示的邮箱列表。
4. 确认继续后，新账户会以**停用状态**建立，不能立即发信或修改服务器邮件，也不会切换当前活跃邮箱。
5. 到“管理邮箱账户／设置”核对 EWS／IMAP／SMTP 信息、目录和服务端权限，重新输入密码，再手动启用或选择账户。

**目前限制：** 配置 JSON 的导入校验接受 `ews`、`imap` 两种协议类型；如果导出的某个账户类型仍是 `tencent`（腾讯企业邮箱预设类型），导入可能被拒绝，请在软件中按腾讯邮箱实际 IMAP/SMTP 参数手动重新建立该账户。不要擅自编辑密码等敏感字段来绕过校验。

**配置 JSON 不包含历史邮件**。需要把邮件正文也带到另一台电脑，请使用“数据保护中心 → 完整备份及隔离恢复”，或本地邮件库的 EML ZIP 导出功能。

## 16. 长期归档与完整性检查

### 16.1 为什么仍要保留“正式归档”？

正式归档是服务器清理操作使用的**独立、可核验**副本；永久本地邮件库用于普通本地邮件客户端体验。两者可以共存，不能把“临时缓存”“永久本地保存”和“满足服务器删除条件的正式归档”简单合并。

### 16.2 手动备份到电脑

1. 在 **邮件** 中选择需要长期保留的邮件。
2. 勾选后选择批量操作“**备份到电脑**”，点击 **执行**。
3. 等待后台任务完成，确认相应邮件出现在 **归档** 页面。
4. 到 **归档 → 检查归档完整性**，执行只读校验。
5. 从归档中打开几封邮件，特别检查正文、中文标题和附件是否可用。

### 16.3 只读完整性检查

“归为旧邮件”“永不删除”等是当前本地分类或保护操作，**不要将其理解为程序默认自动按 365 天移动或删除所有旧档案**。

“检查归档完整性”会核对正式归档的 EML、JSON 元数据和数据库记录，不访问公司邮箱，也不修改或删除文件。发现文件缺失、校验值不一致时会列出问题；**不会替用户静默修复或将损坏归档宣称为完整**。

当前单轮归档只读检查有批次数量限制（本版单次上限约 3,000 条），大型档案库应分批检查，不能把“一轮没有问题”理解为无限量历史记录已经全部扫描完毕。

## 17. 容量监控与安全清理服务器邮件

这是**高风险功能**，仅应由对目标邮箱拥有管理权限、并有权存档或删除邮件的用户使用。

### 17.1 默认容量与保护规则

在 **设置 → 邮件备份与容量提醒**，可以设置：

| 项目 | 常见初始值 | 含义 |
|---|---:|---|
| 邮箱标称总容量 | 2,000 MB | 用户配置的配额参考值，不一定等于服务器实时管理员配额 |
| 高水位 | 1,500 MB | 超过后建议检查清理空间 |
| 低水位 | 1,000 MB | 作为希望回落的参考值 |
| 最小邮件年龄 | 90 天 | 默认只考虑较旧邮件 |
| 跳过未读邮件 | 开启 | 避免未经阅读的邮件被选作清理候选 |
| 跳过加星标邮件 | 开启 | 保护标记重要的邮件 |
| 单次清理批量上限 | 可设 1～1000 封 | 逐封检查；不是“一键无条件删一千封” |

实际占用是软件对可访问邮件项目的**估算**，不等于 Exchange 管理员的真实配额统计。已删除项目、Recoverable Items、组织保留策略可能导致删除之后容量不立即下降。**后台检查容量只负责评估／提醒，不等于默认授权软件自动从服务器永久删除邮件。**

### 17.2 先生成计划，不急着删除

1. 打开顶部 **容量 → 检查邮箱邮件**。
2. 使用关键词、发件人、时间、文件夹、是否符合保护条件等筛选。
3. 查看列表中的时间、大小、备份状态以及是否受保护。
4. 先选择少量自行创建的测试邮件；不要第一次就按上限选中大量重要邮件。
5. 选择删除前如何备份：
   - **使用电脑里已有的完整备份**；或
   - **先备份到电脑，检查完整后再删除**。
6. 选择服务器处理方式：
   - **移到已删除邮件**（通常不会立刻释放配额）；
   - **从服务器永久删除**（可能不可撤销，取决于服务器策略）。
7. 点击 **检查此邮箱能否安全删除邮件**，确认服务端支持相应精确操作。
8. 确认所选邮件及归档状况无误后，才考虑点击 **清理选中的服务器邮件**。

### 17.3 服务器清理的强制保护

软件会重新检查源邮件身份、归档文件、校验结果及服务端操作能力。**没有通过校验不应执行删除**；批处理可能出现部分成功，因此完成后必须查看具体日志。

- EWS：采用对应邮件 ID 的精确服务器操作，并在必要时校验 ChangeKey 等身份信息。
- IMAP：需要服务端支持安全的目标 UID 删除能力，例如 UID MOVE 或 UIDPLUS；**不允许为了清理而退回可能误删整夹其他邮件的普通 `EXPUNGE`**。
- 未读、旗标、近期邮件以及用户设置“永不删除”的邮件有额外保护。
- 更改服务器邮件必须先在 **设置 → 邮件操作** 中明确允许。

### 17.4 “只删服务器、本地保留”

清理目标是**服务器上的指定邮件副本**；本地归档和永久邮件库不应因此被联动删除。完成后可断网再次打开本地归档和永久邮件库，确认保存成功。

**但请注意：** 从服务器删除并不代表所有第三方客户端的本地副本也能保留；其他邮件客户端如何处理源端删除，取决于该客户端自己的同步策略。需要长期保留的邮件应依靠本软件独立归档、永久库及另外的备份。

## 18. 迁移已有归档到新硬盘或新路径

适合 C 盘空间不足、购买新硬盘、调整归档目录结构等场景。

### 18.1 正确操作步骤

1. 先备份原目录，检查新盘空间和可写权限。
2. 结束当前邮箱正在执行的下载、归档、清理任务；必要时停止“本地客户端”网关。
3. 进入 **设置 → 邮件备份与容量提醒 → 迁移已有归档到新的文件夹**。
4. 在**迁移专用输入框**填写新的绝对路径，例如：

   ```text
   E:\MailArchive-New
   ```

5. 点击 **开始迁移／继续中断的迁移**。
6. 到 **后台任务**查看进度；复制过程中可以取消允许取消的任务。
7. 程序会检查复制文件的内容和 SHA-256；**全部核验成功之后**才把当前账户归档路径切换为新目录。
8. 在新目录中打开随机几封邮件，确认正文及附件可读，再执行“归档完整性检查”。

### 18.2 中断后继续

断电、外置磁盘脱机或用户取消后，保持旧目录和已复制的新目录原样，重新连接磁盘并回到同一页面继续任务。目标中已验证的同内容文件可以复用；**遇到同名但内容不同的文件会停止，不应覆盖它**。

不要直接修改数据库或手工剪切整个目录绕过迁移过程。迁移时可能同时存在新旧两份完整文件，需要预留磁盘空间。

### 18.3 哪些目录不建议直接作为归档目录？

- 未经组织批准的个人 OneDrive／其他云同步目录；
- 断网可能导致读写不一致的网络挂载盘；
- 含符号链接或 Windows Junction、实际指向未知位置的目录；
- 容量不足、可能被系统自动清理的临时文件夹。

## 19. 迁移后保留旧目录、提醒与回收站清理

成功迁移之后进入：**设置 → 邮件备份与容量提醒 → 迁移完成：旧归档目录处理**。

### 19.1 三种保留方式

- **保留旧文件，7 天后提醒**（推荐）；
- 保留旧文件，30 天后提醒；
- 保留旧文件，不再提醒。

点击 **保存保留和提醒设置**。提醒到期后，软件的总览和设置页可能显示提示。关闭提醒**不等于删除旧目录**。

### 19.2 清理前必须检查

1. 建议先使用新盘几天，另做一份独立备份。
2. 点击 **检查可清理的旧文件**，阅读核对结果、当前邮箱和旧目录位置。
3. 程序重新核对新旧目录及 EML／JSON SHA-256，拒绝意外新增文件、差异文件或不属于当前邮箱的清理范围。
4. 如果你确实不再需要旧副本，点击 **确认后将本邮箱旧文件移入回收站**。
5. 按确认窗口输入 **`确认清理`**；它是操作确认文字，不是邮箱账号。
6. 到 Windows 回收站检查文件；必要时尝试恢复测试文件。

**限制：** 只自动整理**当前邮箱在旧根目录下的子文件夹**，不删除旧根目录、其他账户文件或上游邮箱邮件。网络共享、无法安全使用回收站、云同步目录或文件校验不通过时，程序会停止自动清理，**不会升级为永久删除**。回收站不是备份。

## 20. 数据保护中心：完整备份与校验

v0.9.9 起提供，v0.9.10 进一步纳入永久邮件库文件（包括已经加密的文件）。

### 20.1 备份包含什么？

| 数据 | 是否纳入 v0.9.10 完整备份 |
|---|---|
| 多邮箱配置 `profiles.json`、应用设置 | **是** |
| SQLite `mailvault.db` 一致性快照 | **是** |
| 正式 EML／JSON 归档与必要元数据 | **是** |
| 永久本地邮件库及其加密文件、加密配置参数 | **是** |
| 归档路径迁移历史记录 | **是** |
| 普通临时下载缓存 `mail_cache` | **不是直接包含**；若有邮件只有缓存副本会阻止声称“完整备份成功” |
| Windows 凭据管理器中的邮箱密码、设备专用密码 | **否** |
| 永久邮件库的用户解锁口令 | **否，必须用户另行保管** |

**完整备份可能包含大量明文企业邮件。** 即使启用了新邮件库加密，历史 EML、数据库元数据和其他内容也可能是明文。未经许可不要把备份直接放入公共网盘或分享链接。

### 20.2 创建完整备份

1. 先等待后台任务结束，停止本地客户端网关。
2. 在顶部打开 **数据保护**。
3. 在“**备份父目录**”填写可用空间充足的本地位置，如：

   ```text
   D:\MailClientManagerBackups
   ```

4. 点击 **创建完整备份**，等待任务执行。
5. 每次备份会生成自己的 `MailClientManager-Backup-<随机ID>` 文件夹。
6. 点击 **逐文件完整验证**，核对文件数量、字节数、SQLite 一致性及 SHA-256。
7. 重要数据建议另保存到经授权的独立硬盘，并定期从备份中实际恢复抽查。

**特别提醒：** 如果弹出“有若干封邮件只有下载缓存、没有正式归档或永久本地副本”，请先到 **本地邮件库 → 转换已下载的完整邮件为永久邮件**，处理失败记录，然后重新创建备份。不要把这种失败的备份文件夹改名冒充成功备份。

### 20.3 中断后的备份续传

在同一备份父目录点击 **查看中断的备份**。未完成备份一般保留 `.partial` 目录；点击对应任务的 **继续该备份**。如果原数据在中断期间发生变化，旧备份可能无法安全续传，应新建一次完整备份。

## 21. 在本机或新电脑隔离恢复数据

### 21.1 恢复操作顺序

1. 在 **数据保护 → 验证备份和恢复预览** 输入完整备份目录。
2. 点击 **逐文件完整验证**。
3. 点击 **验证并预览恢复内容**，检查账户数、EML 文件数量和原始归档位置。
4. 在“**恢复目标父目录**”输入一个**新的独立目录**，例如：

   ```text
   D:\MCM-RestoreSandbox
   ```

5. 输入 `确认恢复`，点击 **恢复到独立目录（不覆盖现有邮箱）**。
6. 程序会在新目录生成 `MCM-Restored-...`，内部有独立的应用数据和按账户归类的 Archives。
7. **恢复不会覆盖当前正在使用的数据库或邮箱配置**。请先在沙盒环境核对恢复的资料。

### 21.2 开发测试电脑如何读取隔离恢复

仅供从完整私人源码启动测试、确认恢复数据的用户使用：

```powershell
$env:EUROSIB_APP_DATA = "D:\MCM-RestoreSandbox\MCM-Restored-实际编号\AppData"
.\.venv\Scripts\python.exe -m eurosib_mail
```

把示例目录替换为页面实际提示的 AppData 路径，在**独立的 PowerShell 窗口**执行。不要与另一份正在写同一数据目录的实例同时运行。恢复的归档位置以该备份恢复的配置和页面结果为准。

普通安装包用户如果没有单独提供恢复目录切换界面，不应自行强行编辑 `mailvault.db` 或用解压文件覆盖正在运行的安装目录；建议先完成验证，再由具备经验的人员进行受控迁移。

### 21.3 跨电脑需要重新配置什么？

- 邮箱账号密码或服务商提供的客户端专用密码；
- 本地 IMAP/SMTP 网关的设备专用密码；
- 已加密永久邮件库的**原始口令**；
- 可能发生变化的磁盘盘符、网络地址、VPN/企业策略；
- 经公司授权的存档路径与备份策略。

## 22. Foxmail、Thunderbird 本地客户端网关

> **高级／实验性功能。** 它为同一台电脑上的第三方邮件客户端提供有限 IMAP/SMTP 接口，不等同于完整 Exchange 协议模拟，也不支持任意远程设备访问。

### 22.1 开启步骤

1. 打开 **本地客户端**，确认显示“未启动”或“运行中”。
2. 为每台设备填写名称或备注，例如“办公室 Foxmail”。
3. 点击 **生成设备密码**，**立即复制并保存**。该密码只显示一次；忘记后应撤销旧记录、创建新记录，而不是要求程序显示旧明文。
4. 在“**设置 → 本地客户端**”查看实际 IMAP、SMTP 端口及邮件来源模式。
5. 点击 **启动本地服务**，确认状态变为运行中；必要时点击“检查文件夹”“检查能否读取邮件正文”。
6. 打开 Foxmail 或 Thunderbird，新建标准 IMAP/SMTP 账户，使用软件页面显示的本地服务器、端口和设备密码。

### 22.2 本机连接参数示例

| Foxmail／Thunderbird 项目 | 填写 |
|---|---|
| 收件服务器地址 | `127.0.0.1` |
| 协议 | IMAP |
| 端口 | 默认约 `21143`，**以软件设置为准** |
| 发件服务器地址 | `127.0.0.1` |
| 协议 | SMTP，开启发件身份验证 |
| 端口 | 默认约 `21025`，**以软件设置为准** |
| 用户名 | 软件当前邮箱地址 |
| 密码 | 本页生成的一次性设备专用密码 |
| 连接加密 | 软件当前示例为**本机环回不额外启用 SSL/TLS**，仅允许同一电脑使用 |

**不要把这些明文本机端口开放到公网或局域网**；`127.0.0.1` 不适合拿来作为另一台电脑直接连接的服务地址。

### 22.3 邮件来源和兼容性

可在设置中选择“**只看已经备份到电脑的邮件**”或“**读取当前邮箱里的邮件**”，更改后可能需要重新启动网关。

本地预览网关的读取能力比写入能力完整。Foxmail 发出修改已读／标星的 `UID STORE` 等命令时，某些操作仍可能被**明确拒绝**；客户端移动、删除、`APPEND`／草稿上传和 `IDLE` 推送均尚未完整支持。软件不会为了消除日志报错而伪造写入成功。

## 23. 后台任务、日志和排障报告

### 23.1 后台任务

打开 **后台任务**，可查看当前和历史的：

- 手动收取／同步邮件；
- 邮箱连接与健康检测；
- 后台邮件正文下载；
- 归档、归档完整性检查、路径迁移；
- 服务器容量检查与清理；
- 完整备份、验证与隔离恢复；
- 本地邮件库导入／导出。

是否能够取消、是否能继续，依赖具体任务类型。**退出程序会停止后台任务；关闭浏览器不一定停止后台任务**。

### 23.2 日志和发送状态

进入 **日志**：可以按关键词、邮箱、严重程度（DEBUG、INFO、WARNING、ERROR）和事件类型筛选；还可以查看发送状态与运行日志。设置页面可以调整日志级别、轮转上限和是否记录邮件主题／地址。

点击 **下载排障报告 TXT** 可导出辅助诊断信息。报告会尽量移除敏感认证材料，但仍可能包含邮箱地址、日期、电脑路径、网络主机名或错误栈。

### 23.3 提交错误反馈的正确方法

1. 记下程序版本、Windows 版本、复现操作和失败发生时间。
2. 到“后台任务”确认哪一步失败。
3. 从“日志”导出 TXT 报告。
4. **人工复查脱敏**：遮盖公司内网、用户名、客户信息及敏感路径；删除口令、令牌、Cookie、NTLM 材料、正文和附件。
5. 在 [GitHub Issues](https://github.com/coderjackzhangwg/MailClientManager-Downloads/issues) 说明“预期发生什么／实际发生什么”，附上不含敏感信息的最小日志片段。

## 24. 软件更新与升级数据保护

### 24.1 检查更新

1. 顶部打开 **软件更新**。
2. 点击 **检查更新**，或者勾选“启用自动检查更新”。
3. 自动检查可选 **每 1 天、每 3 天（推荐）、每 7 天**；默认自动联网检查**关闭**，是否启用由用户决定。
4. 首次启用会加入每安装实例约 **0～6 小时错峰**，避免大量客户端同时访问 GitHub。
5. 最近一小时已经实际请求过时，重复点击通常使用缓存，不会无限增加 GitHub API 请求。
6. GitHub 限流时显示等待信息、保留上次成功获取的说明；可直接打开官方下载仓库查看版本。
7. 根据需要开启“接收测试版（Beta）”，否则可能无法发现预发布版本。

### 24.2 更新说明和下载安装

更新页面可显示 GitHub Releases 中的版本说明及近期历史。当更高版本可用、安装包符合规则并有可核对的校验信息时，允许下载经检查的安装包。**软件不会在后台自动运行下载的 EXE**。

正式升级顺序：

1. 结束后台任务。
2. 到 **数据保护**执行完整备份，至少另行备份当前数据库及实际 EML 目录。
3. 从托盘**完全退出**旧程序。
4. 检查下载的 Setup.exe 文件名、来源和 SHA-256。
5. 双击新版安装包，按向导升级；正常设计保留同一 Windows 用户的应用数据与独立归档。
6. 重新启动并抽查邮箱账号、永久库、加密解锁、正式归档及数据保护页面。

若某版已经在 GitHub 正式发布，维护者应创建新的版本号和 Release，而不是偷偷替换原版本的 EXE。

## 25. 本地存储目录、隐私和安全

### 25.1 文件通常保存在什么位置？

| 数据 | 常见位置／说明 |
|---|---|
| 程序安装文件 | 安装时选择的 Program Files 等位置，与用户邮件数据分离 |
| 应用配置、SQLite、日志和缓存 | `%LOCALAPPDATA%\MailClientManager` |
| 旧版兼容数据目录 | `%LOCALAPPDATA%\EurosibMailManager`；旧安装如果仍在使用，程序可能继续沿用 |
| SQLite 索引 | 实际应用数据目录下 `database\mailvault.db` |
| 多邮箱配置 | `config\profiles.json` |
| 普通离线缓存 | `mail_cache` |
| 默认归档目录 | 用户目录下的 `MailArchive`，旧安装可能使用 `EurosibMailArchive`；**以设置页面实际路径为准** |
| 永久本地邮件库 | 当前邮箱归档根目录下 `profiles\<邮箱标识>\library\...` |
| 永久库加密设置 | 同邮箱目录中的 `library_settings.json`，不保存明文口令 |
| 完整备份 | 用户指定的本地备份父目录，例如 D 盘；不要与系统临时目录混淆 |

**注意：** 更改源码所在 D 盘目录，不等于自动把以前的 `%LOCALAPPDATA%` 数据和 EML 文件迁到了 D 盘。真实归档应以“设置 → 邮件备份保存位置”显示为准。

### 25.2 隐私边界

- 软件主要在用户自己的 Windows 电脑处理邮件数据；正常邮件读取、发送需要连接相应邮箱服务器。
- 手动或自动检查软件更新会访问 GitHub；GitHub 可获得请求 IP 等普通网络信息。
- 默认不把邮件正文、附件、邮箱密码和诊断报告上传到开发者服务器。用户自行上传到 GitHub Issue、云盘或第三方存储属于另外的操作。
- 当前存档、数据库元数据和备份中可能有**未加密明文**；请采用受控目录、磁盘保护与独立备份。
- 企业邮箱应事先获得合法使用和数据保留授权。即使邮件存在个人电脑，也不代表可以未经许可删除企业服务器邮件。

## 26. 推荐的三种使用流程

### 场景 A：普通邮件客户端，尽量少做服务器修改

1. 在设置中添加邮箱，测试连接。
2. 保持“允许修改服务器上的邮件”关闭。
3. 选择“打开后保存”或“后台下载”以便离线阅读。
4. 需要长期保存时开启本地永久邮件库自动保存。
5. 定期在“数据保护”创建完整备份。

### 场景 B：2GB 容量的企业邮箱，安全地释放服务器空间

1. 先取得组织允许归档和服务器清理的授权。
2. 完整下载需要保存的邮件，并另存为**正式 EML 归档**。
3. 检查 EML、附件和哈希；再创建独立完整备份。
4. 到“容量”页面查看**估算**占用及旧邮件候选。
5. 先用少量无价值的测试邮件检查服务端删除能力。
6. 明确选择“移到已删除邮件”或“永久删除”，验证服务器确实按预期处理。
7. 清理后断网检查本地归档和永久邮件库仍能阅读。

### 场景 C：换电脑或迁移到大硬盘

1. 在旧电脑完成正式归档和永久库转换。
2. 创建完整备份并完成逐文件校验。
3. 将备份复制到经批准的受控存储介质，保存好加密口令。
4. 在新电脑安装程序，不要直接覆盖新电脑正在运行的 SQLite。
5. 使用数据保护中心**隔离恢复**，核对账户、邮件与附件。
6. 重新输入邮箱密码和设备专用密码，重新验证网络及归档路径。
7. 若只是换归档磁盘，则使用 **设置中的专用迁移任务**，验证后才整理旧目录。

## 27. 功能限制与兼容性说明

以下是 v0.9.10 当前实际范围，**不是未来功能路线图**：

| 项目 | 已实现或限制 |
|---|---|
| 可连接邮箱 | EWS、IMAP/SMTP；具体依赖组织允许的协议及认证方式 |
| Outlook 专有格式 | **暂不直接导入 PST／OST**；需先转换 |
| EML/MBOX/Maildir | 支持本地导入导出，但有单次 500 封／512 MiB 限额 |
| EML ZIP | 本软件格式需要有效 `manifest.json` 和 SHA-256，普通 ZIP 不一定兼容 |
| 邮件永久保存 | 需要启用或手动转换；下载缓存不会自动全部变成永久保存 |
| 可选加密 | 仅作用于启用后新写入的永久邮件文件；旧正文、缓存、索引、备份不自动加密 |
| 邮件正文搜索 | 主要基于已有本地索引；大规模数据性能须在用户电脑测试；不索引附件内所有内容 |
| 归档完整性检查 | 只读，单轮有数量上限；不会自动修复坏文件 |
| 服务器容量 | 通常是邮件大小估算，不等于真实 Exchange 管理配额 |
| 服务器删除 | 须有正式归档与身份校验；缺少安全 UID 操作能力的 IMAP 服务会被拒绝 |
| 归档迁移 | 支持复制校验、断点继续；旧文件不会在切换路径时自动删除 |
| 旧目录清理 | 只处理符合条件的当前邮箱旧子目录，尝试回收站，不永久删除整个根目录 |
| 完整备份 | 含永久库、正式归档和 SQLite；不直接备份可重建缓存，也不含密码／恢复口令 |
| 隔离恢复 | 恢复到新目录而不是自动覆盖当前正在运行的数据库 |
| 本地网关 | 实验性 IMAP/SMTP；写入／移动／删除／IDLE／APPEND 等有不完整功能 |
| GitHub 更新 | 保留速率限制冷却与说明缓存；只下载校验安装包，不自动执行 |
| 平台 | 面向 Windows 桌面环境，非云端多租户平台，不保证 macOS/Linux 原生桌面体验 |

## 28. 常见问题与排查

**Q1：自动下载完成了，为什么“归档”里找不到？**  
A：自动下载先建立离线缓存。正式 EML 归档和永久邮件库是独立的。可以在邮件工作区使用“备份到电脑”，或到“本地邮件库”开启自动永久保存／转换已有完整缓存。

**Q2：我想只删服务器邮件，电脑里一直保留，可以吗？**  
A：可以使用经过归档验证的服务器清理路径，同时保留正式归档与永久库。但**必须先成功保存、校验**；不能凭缓存列表就删服务器原件。其他邮件客户端是否保留自己的本地副本由它们决定。

**Q3：我启用了 AES-GCM，为什么旧 EML 仍能在资源管理器里直接打开？**  
A：此选项只加密今后新保存的永久邮件，不追溯转换旧文件；SQLite 元数据、缓存和历史备份也不会自动被加密。

**Q4：新电脑可以用配置 JSON 直接恢复全部邮件和密码吗？**  
A：不可以。JSON 只有非秘密配置；历史邮件和 SQLite 请使用完整备份与隔离恢复，邮箱密码与设备密码需要重新设置，加密邮件仍需原恢复口令。

**Q5：为什么“完整备份”提示有邮件只在缓存中？**  
A：为了防止漏备份，程序会拒绝错误地报告成功。先到本地邮件库将这些完整缓存转为永久文件，解决失败项后重新备份。

**Q6：旧硬盘迁移成功后能直接删除旧文件夹吗？**  
A：先检查迁移完整性和新盘可读性，再按设置中的“检查可清理的旧文件”操作；程序只对当前邮箱的旧子目录提供回收站清理，不直接删除旧根目录或其他邮箱文件。

**Q7：为什么清理旧目录要求输入“确认清理”？**  
A：这是本地旧归档回收站操作的二次确认。它**不是**企业邮箱账号密码，也不代表服务器邮件清理授权。

**Q8：为什么 IMAP 删除提示缺少 UID MOVE／UIDPLUS？**  
A：服务器不支持必要的精确操作。软件会拒绝可能影响文件夹中其他邮件的普通 EXPUNGE。不能为了删除成功而关闭这条保护。

**Q9：本地客户端生成的密码忘了怎么办？**  
A：设备密码只显示一次；可创建新密码并撤销旧记录。它与原企业邮箱密码不是同一回事。

**Q10：Foxmail 能收邮件，但标为已读／移动邮件失败？**  
A：本地 IMAP 网关当前主要适用于预览和读取；某些 UID STORE 等写命令尚未完整支持。拒绝写入是预期保护，不是伪造成功。

**Q11：我正在用公司 VPN，但连接测试显示 TLS 超时？**  
A：检查是否能访问公司的 EWS/IMAP 入口、企业代理是否要求单独配置、Java／Python 是否使用同一路径。手动连接检测和后台下载是不同操作，不能仅凭“在线”推断所有请求成功。

**Q12：GitHub 返回 403 是不是软件账号被封？**  
A：不一定。未认证 GitHub API 有共享公网 IP 速率限制；只有配额头或 Retry-After 等证据才应判断为限流。稍后再检查或直接打开公开 Releases。

**Q13：MBOX 重新导入后 SHA-256 和原始容器不同正常吗？**  
A：MBOX／Maildir 转 EML 时可能发生重序列化。需要字节级 EML 保真时，优先使用带独立 SHA-256 的 EML ZIP。

**Q14：旧版安装升级后，账户怎么不见了？**  
A：先确认是不是换了 Windows 用户、应用数据目录或使用了带 `EUROSIB_APP_DATA` 的测试启动方式。新目录 `%LOCALAPPDATA%\MailClientManager` 与历史 `%LOCALAPPDATA%\EurosibMailManager` 可能不同。**不要覆盖旧数据库**；先查看完整备份和账户目录，再在隔离环境恢复。

**Q15：为什么软件更新说明没有展示新版本？**  
A：核对当前版本号、目标 GitHub Release 是否已公开、Beta 开关是否匹配，以及最近一小时是否已经查过。直接打开 GitHub 发布页面不依赖软件更新按钮。

**Q16：能否把完整源码和我的邮箱备份上传 GitHub 来求助？**  
A：不建议。公开 Issue 只分享必要的**脱敏错误内容**，不上传完整 EML、数据库、密码或企业内部资料；当前私人源码也不应作为普通安装资产公开。
